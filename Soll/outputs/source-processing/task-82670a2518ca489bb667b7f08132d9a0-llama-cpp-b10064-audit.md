## Local-impact decision

Keep the verified b9895 manifest and backend route. Do not add an Android native
dependency, package b10064 binaries, or change runtime configuration from this
signal. A standalone b10064 release rollout would duplicate the device/driver
harness of the documented later b10066 OpenCL/Adreno candidate without a current
applicable workload. If both distinct dense Q4_K and MoE workloads materialize,
they belong in separate rows of one approval-gated benchmark matrix.

The knowledge note defines six gates for any later consolidated benchmark:
pinned device/driver and kernel path, applicable dense Q4_K model, repeated
performance/resource measurements, correctness and tensor round-trip, a `10%`
promotion threshold, and retained b9895/backend rollback.
