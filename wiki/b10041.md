# llama.cpp b10041: применимость к Soll app

Дата проверки: 2026-07-22.

## Решение

`b10041` сейчас не требует изменения Android-приложения, Retrofit-контракта,
runtime route или standalone manifest. Релиз исправляет только шум в логах
`llama-server`: при `cors_origins == "localhost"` server больше не пишет
предупреждение `skip non-localhost origin` для запроса без заголовка `Origin`
или с пустым `Origin`.

В production Android нет прямого HTTP/CORS-контракта с `llama-server`:
`SollApiService` отправляет chat turn через существующий
`POST api/v1/chat/turn`, а policy оставляет `soll-backend-route` default и не
упаковывает llama.cpp binary в APK. Активный standalone verification baseline
уже pin-ит более новый `b10068`; официальный upstream compare показывает, что
он на `27` commits впереди `b10041`, на `0` commits позади и имеет commit
`8ee54c8b32a1b0cf13c03fc5723142bc62c775f6` как merge base. Поэтому отдельное
обновление до b10041 не нужно.

Локальная применимость условная: если появится отдельно одобренный
`llama-server` HTTP workload с `--cors-origin localhost`, исправление сохранит
логи читаемыми для native/CLI clients, которые обычно не отправляют browser
`Origin`. Это observability hygiene, а не CORS security fix, новый API или
ускорение inference.

## Что изменяет b10041

В ветке `cors_origins == "localhost"` server читает
`req.get_header_value("Origin")` и теперь проверяет `!origin.empty()` перед
двумя действиями:

1. Непустой localhost origin по-прежнему отражается в
   `Access-Control-Allow-Origin`.
2. Непустой non-localhost origin по-прежнему не отражается и создаёт
   предупреждение.
3. Отсутствующий или пустой origin не отражается и больше не создаёт ложное
   предупреждение с пустым значением.

HTTP status, response body, CORS allow policy и inference path не изменяются.
В релизе нет benchmark или подтверждения влияния на latency/throughput.

## Пять проверенных seam Soll app

| Seam | Факт в репозитории | Следствие для b10041 |
| --- | --- | --- |
| Android chat contract | `SollApiService.sendChatTurn()` вызывает `POST api/v1/chat/turn` | Не добавлять direct llama-server URL или CORS logic в Retrofit |
| Android runtime policy | `androidRuntimeDefault` — `soll-backend-route`, `packageIntoAndroidApp` — `false` | b10041 не меняет пользовательский runtime |
| Standalone baseline | `llama_cpp_active_defaults.json` pin-ит `b10068` | Fix уже включён в проверяемый standalone release |
| Standalone execution | Verification scripts запускают `llama-server` только с `--version`; CORS/server HTTP config не найден | Текущий smoke не воспроизводит исправляемое предупреждение |
| Model gate | `approved_models.json` содержит `models: []` | Нельзя запускать model-backed HTTP smoke без отдельного provenance approval |

В production app также нет собственного llama.cpp CMake/JNI/server adapter.
Имеющиеся `jniLibs` относятся к другим локальным runtime и не являются точкой
внедрения server-side CORS patch.

## Ворота будущего измеримого smoke

Отдельный runtime smoke оправдан только при появлении одобренного прямого или
server-adapter workload. Он должен:

1. Зафиксировать host, llama.cpp commit, asset SHA-256 и одобренный GGUF из
   allowlist; не включать binary или model в APK/AAB.
2. Запустить `llama-server` с `--cors-origin localhost` и сохранять только
   несекретный test log.
3. Для серии запросов без `Origin` и с пустым `Origin` получить ожидаемые
   HTTP-ответы, `0` пустых CORS warnings и отсутствие
   `Access-Control-Allow-Origin`.
4. Для localhost origin подтвердить отражённый
   `Access-Control-Allow-Origin` и отсутствие warning.
5. Для non-localhost origin подтвердить отсутствие allow header и сохранённое
   предупреждение, то есть отсутствие расширения CORS policy.
6. Сравнить parent `c7d8722922a2599dc4d77f8808d8e6c2fde5e7a2` с b10041
   или проверить включающий fix b10068; HTTP/API regressions, crashes и
   неожиданные CORS grants должны быть `0`.
