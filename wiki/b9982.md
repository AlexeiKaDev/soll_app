# llama.cpp b9982: применимость к Soll app

Дата проверки: 2026-07-23.

## Решение

`b9982` не требует изменения Android-приложения, Retrofit-контракта или
standalone manifest. Релиз исправляет разбор OpenAI-compatible chat completion
в `llama-server`: canonical поля запроса `reasoning_budget_tokens` и
`reasoning_budget_message` теперь имеют приоритет над server defaults, поэтому
per-request override больше не отбрасывается.

В текущем Soll Android `ChatTurnRequest` отправляет только `session_id`,
`content`, `metadata`, `encrypted`, `run_assistant` и `task_intake` через
`POST api/v1/chat/turn`. В `app/src/main` до этой оценки было `0` точных
упоминаний `reasoning_budget_tokens`, `thinking_budget_tokens` или
`reasoning_budget_message`; прямого OpenAI-compatible контракта с
`llama-server` нет. Runtime policy оставляет `soll-backend-route` default и не
упаковывает llama.cpp binary в APK.

Активный standalone verification baseline уже pin-ит более новый `b10068`.
Официальный upstream compare показывает, что он на `86` commits впереди
`b9982`, на `0` commits позади, а commit b9982
`99f3dc32296f825fec94f202da1e9fede1e78cf9` является merge base. Поэтому
отдельный rollout b9982 и расширение Android DTO сейчас не дают измеримой
runtime-ценности.

## Что исправляет b9982

До исправления reasoning-budget block в `oaicompat_chat_params_parse()` читал
Anthropic-style alias `thinking_budget_tokens` или server default, записывал
результат в `llama_params`, а последующий generic body-copy уже не мог
перезаписать ключ. Поэтому canonical request override
`reasoning_budget_tokens`, включая `0` для подавления thinking, игнорировался.
Аналогично `reasoning_budget_message` всегда брался из server default.

После b9982:

1. `reasoning_budget_tokens` читается первым, затем
   `thinking_budget_tokens`, затем server default.
2. `reasoning_budget_message` читается из request body с fallback на server
   default.
3. Изменение действует в reasoning-budget path chat template с thinking tags;
   upstream unit tests используют Qwen3 template.
4. Endpoint, response schema, модельный runtime и server defaults не меняются.
5. Upstream test проверяет override tokens со значением `0` и отдельный
   per-request override сообщения.

Это correctness fix для server adapter, которому нужен управляемый
per-request thinking budget, а не общий прирост latency или качества модели.

## Пять проверенных seam Soll app

| Seam | Факт в репозитории | Следствие для b9982 |
| --- | --- | --- |
| Android chat contract | `SollApiService.sendChatTurn()` вызывает `POST api/v1/chat/turn` | Не добавлять direct `/v1/chat/completions` contract |
| Android request DTO | `ChatTurnRequest` не содержит три reasoning-budget поля | Не раскрывать llama.cpp-specific параметры без отдельного product contract |

| Model gate | Allowlist deny-by-default; единственный tiny fixture разрешён только для b9945/b9947 smoke | Нет одобренного reasoning-capable model workload для b9982 HTTP smoke |

## Место будущего применения

Если server-side inference adapter за `POST api/v1/chat/turn` получит
одобренный reasoning-capable `llama-server`, именно adapter может сопоставлять
высокоуровневую продуктовую policy с `reasoning_budget_tokens` и
`reasoning_budget_message`. Android не должен напрямую владеть
llama.cpp-specific alias или server default.

Adapter обязан валидировать допустимый диапазон budget, ограничивать размер и
содержимое message, не сохранять параметры между запросами и явно определять,
может ли пользователь выбирать режим без thinking. До появления такого
контракта текущие `ChatViewModel`, `SollRepository`, `SollApiService` и
`ChatTurnRequest` остаются без изменений.

## Ворота будущего измеримого smoke

Отдельный runtime smoke оправдан только после pin одобренных model GGUF, chat
template, llama.cpp commit и target host. Он должен:

1. Запустить b9982 или включающий fix b10068 с ненулевым server default и
   reasoning-capable template.
2. Отправить canonical `reasoning_budget_tokens: 0` и доказать, что sampling
   получает `0`, а не server default.
3. Отправить уникальный `reasoning_budget_message` и доказать, что используется
   per-request value.
4. Проверить precedence canonical field над `thinking_budget_tokens`, а также
   fallback на alias/default при отсутствии canonical field.
5. Повторить разные budgets последовательно и параллельно: cross-request или
   cross-session leakage должен быть `0`.
6. Подтвердить неизменные HTTP status/response schema, `0` crashes и `0`
   неожиданных раскрытий hidden reasoning; сохранить только несекретный audit
   result.
